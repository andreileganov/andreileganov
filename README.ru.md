**Работа с агентами**

Последний год пишу инструменты для работы с кодовыми агентами — и пишу их с агентами. Вывод, к которому пришёл: надёжность даёт не удачный промпт, а ограничения вокруг агента, то есть проверки, которые срабатывают без участия человека.

- **[threadcode](https://github.com/andreileganov/threadcode)** — десктопный клиент (macOS, Electron), где разговор ветвится тредами, как в Slack. Тред знает весь контекст родителя, обратно ничего не утекает, обе панели работают одновременно. У треда свой git worktree и своя ветка, поэтому его правки не трогают основную работу. Изоляция проверена живыми прогонами против настоящего SDK, а не заглушек: кодовое слово, выданное родителю, тред назвал, а слово, известное только треду, родитель не знал. Исходники открыты: 70 коммитов, 23 файла тестов, около 8700 строк.
- **Сначала обвязка, потом код.** Хуки запрещают коммит в `main`, запись вне проекта и чтение `.env`. В каждый запрос подмешиваются текущая ветка, незакоммиченные файлы и незакрытые критерии приёмки. На остановке — гейт качества: типы, линтер, тесты.
- **Про spec-driven.** Тест, написанный после кода и по коду, доказывает лишь, что код делает то, что делает. Тест, написанный из критерия приёмки, доказывает, что код делает обещанное. Файлы выглядят одинаково, смысл противоположный.
- **Личный агент** на Claude Code, живёт на сервере: задачи, календарь, заметки. Интересны в нём не функции, а двенадцать хуков, которые не дают ему нарушить собственные правила — в том числе запрет утверждать, что чего-то не существует, пока не проверен первоисточник. У каждого инструмента самопроверка, один прогон проверяет их все.
